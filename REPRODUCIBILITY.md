# Reproducibility Guide

## 1. Offline statistical reproduction (recommended)

The committed merged outcome journal contains all 2,190 turn-level outcomes needed to recompute the paper's confirmatory H1-H3 statistics. No model weights, GPU, API key, or network access are needed.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .
python release_tools/run_frozen_tests.py
python release_tools/verify_public_release.py
python release_tools/analyze_pilot20.py
python release_tools/verify_human_audit.py
python release_tools/make_publication_tables.py
python release_tools/robustness_audit.py
```

Expected endpoints:

```text
Ran 149 tests ... OK
PUBLIC_RELEASE_INTEGRITY=PASS
REPORTED_CORE_STATISTICS=EXACT_MATCH
HUMAN_AUDIT_PUBLIC_COUNTS=EXACT_MATCH
ROBUSTNESS_AUDIT=COMPLETE
```

`release_tools/analyze_pilot20.py` writes recomputed outputs under `results/recomputed/` and checks the recomputed core statistics against the authoritative frozen `pilot20_analysis.json`.

## 2. Why a release wrapper exists

The repository's original `analyze` command was designed for the full 100-base held-out protocol and correctly rejects an incomplete full-design run. The application/preprint pilot was a compute/time amendment fixed at 20 bases before held-out performance inspection. The release wrapper reuses the frozen metric and bootstrap implementation but validates completeness against that amended denominator.

No file under the source-frozen scientific implementation is modified by the release wrapper.

## 4. Inference reproduction

The exact primary model/runtime used for held-out inference was:

- `Qwen/Qwen3-8B`
- revision `b968826d9c46dd6066d109eabc6255188de91218`
- vLLM `0.29.0`
- Transformers `5.17.0`
- PyTorch `2.13.0+cu130`
- CUDA `13.0`
- BF16
- seed `263901`
- non-thinking mode (`enable_thinking=false`)
- server fingerprint `vllm-0.29.0-33dd102b`

Frozen sampling: temperature 0.7, top-p 0.8, top-k 20, min-p 0, max tokens 1800.

The first five pilot bases were executed serially. The remaining fifteen were executed with five concurrent between-base workers under a written amendment; within each base, the frozen `run_case` trajectory execution remained sequential. Repeated seeded stochastic generation was not assumed bitwise deterministic across batching regimes.

Model weights are not redistributed. The upstream revision and per-file weight hashes are retained in provenance.

## 5. Human audit reproduction

The public audit release contains:

- `human_overall_ratings.csv` - the final overall human judgment for each `audit_id`;
- `audit_deblinding_key.jsonl` - mapping from `audit_id` to architecture, condition, base, and outcome key;
- `human_audit_descriptive.json` - authoritative descriptive aggregate;
- `auditor.json` - rater scope and limitations.

Run:

```bash
python release_tools/verify_human_audit.py
```

The original free-text rationales and optional UI subfields are not necessary to reproduce the reported aggregate and are not included in the public release. Their exact full-file hash remains recorded in the frozen final-analysis manifest.

Because automated semantic labels were unavailable in `manual_audit_only` mode, the audit cannot reproduce sensitivity/specificity/kappa against an automated semantic evaluator; that arm was not tested.

## 6. Publication-only secondary analysis

`release_tools/make_publication_tables.py` derives condition-level C-B effect tables from the already frozen outcomes. This is a post-freeze descriptive decomposition for presentation. It performs no model calls and does not change the prospective hypotheses, denominators, architectures, or primary analysis.

## 7. Bootstrap and robustness reproduction

The frozen confirmatory confidence intervals are generated by `paired_ratio_bootstrap` in `src/psyr/analysis/statistics.py`. It resamples **paired cluster IDs** with replacement, so both compared arms use the same resampled held-out base trajectories. The frozen settings are 2,000 repetitions and seed `77129`.

`release_tools/robustness_audit.py` adds post-freeze, analysis-only checks:

- 10,000-draw paired bootstrap using the frozen seed;
- five fixed bootstrap seeds at 2,000 draws;
- context-family clustering as an alternative dependence unit;
- leave-one-base-out influence ranges;
- the prespecified H3 `ALL_REFERENCE` sensitivity aggregate.

The script writes `results/publication/robustness_audit.json` and `results/publication/robustness_summary.json`. These are explicitly secondary robustness diagnostics and do not modify the frozen prospective hypotheses or primary analysis.

## 8. Reproducibility levels

This repository supports **exact offline reproduction of the reported statistics** from the committed 2,190 frozen outcomes. It also includes the benchmark, frozen scientific implementation, prompts, exact model revision/runtime/sampling settings, amendments, and hashes needed to re-execute the inference protocol.

Full **bitwise regeneration of the original model text is not claimed**: the model weights are not redistributed, and the original inference used seeded stochastic decoding with a mix of serial and between-base concurrent execution. The raw held-out execution archive is provenance-preserved by SHA-256 in the frozen manifest, while the committed merged outcome journal is the publication artifact required for exact analysis reproduction.

## 9. Interpretation boundaries

Reproducibility of the software and statistics does **not** establish:

- clinical validity of the ontology;
- therapeutic efficacy;
- patient safety;
- generalisation to real users or longer interactions;
- cross-model robustness;
- independent semantic validation of response quality.

The benchmark is synthetic and non-clinical by design.
